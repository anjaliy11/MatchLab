# Card-tier annotation packet

## Purpose and status

This packet defines the approved policy rubric and the process for collecting
an initial human-adjudicated tier set. A separate policy-labelled synthetic
baseline now exists at `evals/data/card_tier_policy_seed.csv`, generated by
`scripts/generate_card_tier_policy_dataset.py`. That baseline is not a
measured compiler evaluation: its expected tiers are copied from the approved
rubric, its predictions come from the rule-based stand-in, and no human has
rated or adjudicated the rows. Do not describe it as human-adjudicated.

No external dataset is used. Public PII corpora label whether text spans
contain PII; they do not define matchlab's `never` / `coarse` / `exact` tiers
at BLIND and MUTUAL stages. For example, [Ai4Privacy PII Masking 200k](https://huggingface.co/datasets/ai4privacy/pii-masking-200k)
describes synthetic PII spans and human-in-the-loop validation, while the
[Kaggle PII detection/removal collection](https://www.kaggle.com/datasets/nbroad/pii-dd-mistral-generated)
is synthetic PII-detection data. Neither provides the policy labels required
here. These sources were not downloaded or included.

## Approved policy for this packet

These labels express the approved annotation policy, not claims about a
product's existing behavior:

| Category | BLIND | MUTUAL |
|---|---|---|
| employer | coarse | exact |
| city | coarse | exact |
| school | never | exact |
| religion | never | never |
| health | never | never |
| sexual_orientation | never | never |
| caste | never | never |
| politics | never | never |
| immigration | never | never |
| finances | never | never |
| hobby | exact | exact |
| sector | exact | exact |
| region | exact | exact |

Tier meanings:

- `never`: disclose no form of this fact at that stage.
- `coarse`: disclose only a generalized form that does not reveal the exact
  fact.
- `exact`: the exact fact may be disclosed at that stage.

## Rater procedure

1. Give both raters an identical copy of `evals/data/card_tier_labels_template.csv`.
2. Raters independently fill only their own `rater1_*` or `rater2_*` columns
   using the policy table above. Do not discuss cases before submitting.
3. A third person reviews disagreements, records the final tier in each
   `adjudicated_*` column, and keeps a brief rationale outside the evaluator
   CSV. Do not add names, fact text, profiles, or restricted values to the CSV.
4. Preserve the two independent submissions and adjudicated copy in an
   approved local/offline location. Do not upload annotation materials to a
   public dataset or third-party service.
5. The template is not accepted by `scripts/eval_card_tiers.py`: it has no
   compiler predictions or confidence scores. Only after a compiler that
   emits predictions and confidence exists should its outputs be joined to
   adjudicated labels using `item_id` and supplied to that evaluator.

## Policy-labelled stand-in baseline

Regenerate the privacy-minimal baseline and its aggregate report with an
explicit seed:

```powershell
python scripts/generate_card_tier_policy_dataset.py --seed 0
```

Each category appears once. `expected_blind` and `expected_mutual` encode the
approved rubric. Predictions are extracted from `compile_card` only for
categories that the stand-in actually emits; unsupported categories are
`unknown`. Confidence columns are intentionally blank because this compiler
has no confidence interface. The report declares label provenance, prediction
source, unsupported categories, and stage-wise policy agreement.

The baseline checks only whether the current stand-in happens to implement
the approved mapping for its supported categories. It is by construction,
not an independent accuracy measurement. It has no profile values, no
human-rater columns, and is not input to `scripts/eval_card_tiers.py`.
Meaningful compiler evaluation still requires representative synthetic facts,
actual predictions and confidence from the compiler under test, two
independent raters, and a documented adjudication process. Keep
fact-bearing review material in the approved offline process.
